# Промышленная backend-разработка на Go — autumn 2026

11 заданий task_00–task_10, 8 занятий, Go **1.27.1**, только стандартная библиотека.

## Начало работы

1. Сделайте fork `ippaveln/industry_backend_go_autumn_2026`, основная ветка — `master`.
2. Установите Go 1.27.1: https://go.dev/dl/ . Проверьте `go version`.
3. Реализуйте функции в `tasks/task_XX/solution.go`. Заготовки компилируются, но намеренно вызывают panic TODO; все тесты в начале проходить не должны.
4. Запускайте `go test -race -count=4 ./tasks/task_XX`. Демонстрация: `go run ./tasks/task_XX`.
5. Создайте PR из форка в `master` исходного репозитория. Заголовок: `ИСУ 123456`.

## Правила сдачи

Разрешено менять только 11 существующих `tasks/task_00/solution.go` … `tasks/task_10/solution.go`.
Нельзя менять, добавлять или удалять другие файлы, подменять их символическими ссылками, подключать внешние зависимости или cgo. Компиляторные директивы `//go:` и build tags запрещены: решение должно проверяться тем же способом, что и опубликованные тесты.

Условия в README каждого задания — полный контракт. Скрытых требований нет. Все преподавательские тесты опубликованы; преподавательские реализации в этот репозиторий не входят.
AI-инструменты разрешены, но на экзамене нужно объяснить собственное решение.

## Проверка и бейджи

Официальная проверка — workflow `autumn-grade` **в исходном репозитории** при PR. Она использует преподавательские конфигурацию, тесты и проверяющий код на Go из `ippaveln/industry_backend_go_autumn_2026`, ветка `master`. Сначала сравниваются файлы, затем к преподавательским тестам подставляются только разрешённые решения.
Код студента запускается в контейнере без сети, секретов и токена записи; исходники доступны только для чтения. Временные файлы сборки разрешены в /tmp контейнера.

Задание проходит только при статусе `pass` и соблюдении правил файлов. `fail`, `missing`, `unknown`, пропуск теста и отсутствие отчёта успехом не считаются. Незавершённые задания делают общий workflow красным; результаты каждого задания видны в артефакте `autumn-results/package-results.json`.

Бейджи пересоздаются для **каждого запуска** и находятся в артефакте `autumn-results/badges/tasks/`. Начальные SVG в `badges/tasks/` имеют статус unknown. CI не коммитит изображения в `master`: это сохраняет правило «меняются только solution.go» и исключает токен записи из проверки. Актуальный результат смотрите в артефакте конкретного PR/SHA, а не в начальных SVG. Проверка в форке информационная; изменение workflow форка не меняет официальную проверку.
