# Как устроена проверка

## Официальная проверка

Результат определяет workflow `autumn-grade` этого репозитория на PR. Проверяющий код, тесты и сам workflow берутся из `master` этого репозитория; из PR — только файлы `solution.go`.

1. Файлы PR сравниваются с `master`, `solution.go` проверяются на ограничения из [README](README.md#правила).
2. Все задания собираются с `-race` в Docker-контейнере без сети и секретов; исходники смонтированы только на чтение.
3. Тесты каждого задания запускаются в отдельном контейнере с `-count=4 -timeout=60s`.

Задание засчитывается, если каждый тест прошёл все 4 раза и нет упавших или пропущенных тестов. Результат каждого задания — отдельный check `task_XX` в PR. Вывод тестов — в артефакте `autumn-results`, файл `task_XX.jsonl`.

## Форк и бейджи

В форке workflow запускается при каждом push в `master` и коммитит обновлённые `badges/tasks/task_XX.svg`, поэтому бейджи в таблице заданий и в README каждого задания показывают результат последнего push. В новом форке Actions выключены: включите их на вкладке **Actions**.

GitHub кэширует картинки из README до 5 минут, поэтому бейдж обновляется с задержкой. Чтобы увидеть его сразу, обновите страницу без кэша (Cmd+Shift+R или Ctrl+Shift+R). Результат прогона сразу виден на вкладке **Actions** форка.

Из-за коммитов бота перед `git push` нужен `git pull --rebase`. Чтобы не указывать флаг каждый раз: `git config pull.rebase true`.

Проверка в форке только информационная: изменения workflow в форке на официальную проверку не влияют.
