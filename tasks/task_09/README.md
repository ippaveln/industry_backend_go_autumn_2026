# task_09: Worker pool: независимые результаты

![task 09](../../badges/tasks/task_09.svg)

Объявите `type Result[R any] struct { Value R; Err error }`, sentinel `ErrInvalidWorkers` и `func ParallelMap[T any,R any](ctx context.Context, workers int, in []T, fn func(context.Context,T)(R,error)) ([]Result[R],error)`. Каждый элемент обрабатывается ровно один раз, одновременно не более workers вызовов, и пока есть невыданные элементы, пул держит занятыми все min(workers,len(in)) воркеров; горутин O(min(workers,len(in))), без горутины на элемент. Результаты сохраняют порядок входа. Ошибка fn записывается в соответствующий Result.Err (errors.Is должен работать), Value при ошибке — zero R; **ошибка элемента не отменяет остальные вызовы**, общая ошибка остаётся nil. При отмене родительского контекста прекратить выдачу, передать отмену уже работающим fn, дождаться их и вернуть nil,ctx.Err(). Уже отменённый контекст не запускает fn, включая пустой вход. Fn обязана завершаться при отмене; паники fn не обрабатываем. Workers<=0 проверяется первым и даёт nil,ErrInvalidWorkers. Пустой вход при действующем контексте → пустой срез,nil. Nil ctx/fn не входят в контракт. После возврата все рабочие горутины завершены. Пример с workers=1: ошибка на первом элементе не мешает получить успешный второй результат.

Меняйте только solution.go. Используйте stdlib. Проверка: `go test -race -count=4 ./tasks/task_09`.
